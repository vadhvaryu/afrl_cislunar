# AFRL Cislunar Orbit Determination

NewSpace@Berkeley x Air Force Research Laboratory, Fall 2026.

This repository contains the developing software stack for the NewSpace@Berkeley x AFRL containerized cislunar orbit-determination project.

The current implementation uses synthetic spacecraft observations to test methods for estimating an initial spacecraft state, refining that estimate, propagating the resulting orbit, and evaluating the results. The current simulation focuses on the Earth-Moon Circular Restricted Three-Body Problem (CR3BP), with Orekit used for orbit-determination and propagation components.

## Purpose

The goal of this project is to develop a containerized software pipeline for orbit determination in cislunar space.

The software is designed to:

- Accept noisy spacecraft observations
- Produce an initial orbit estimate
- Refine that estimate using orbit-determination methods
- Propagate the estimated trajectory
- Track estimation uncertainty
- Compare estimated trajectories against synthetic reference data
- Allow different methods to be selected through a configuration file
- Package the full workflow into a portable container

## Primary Design Goals

### Modular Simulation Stack

Each major stage is separated so that methods can be changed without rewriting the rest of the program.

The current pipeline is:

```text
Observation data
      ↓
Observations
      ↓
Initial Orbit Determination (IOD)
      ↓
StateEstimate
      ↓
Batch Least Squares estimation
      ↓
Refined StateEstimate + covariance
      ↓
Trajectory propagation
      ↓
Trajectory
      ↓
Results, plots, CSV, and JSON
```

### CR3BP Cislunar Dynamics

The current dynamics model uses the Earth-Moon CR3BP. This provides a simplified model of cislunar motion while accounting for the gravitational influence of both Earth and Moon.

### Configurable Methods

`config.yaml` controls the methods and parameters used in each stage of the simulation. This allows the user to change IOD, estimation, and propagation methods without modifying the main pipeline.

### Higher-Fidelity Expansion

The current software is structured so that the simplified CR3BP model can later be expanded with more detailed force models, real ephemerides, and higher-fidelity dynamics.

## Stack Architecture

The main orbit-determination code is located in `od_stack/`.

### `od_stack/run.py`

Main entry point for the simulation.

It performs the following steps:

1. Loads observations
2. Runs the selected IOD method
3. Refines the estimate using the selected estimator
4. Propagates the resulting state
5. Generates results and output files

### `od_stack/contracts.py`

Defines the main data objects shared between modules:

- `Observations`
- `StateEstimate`
- `Trajectory`

These shared objects allow different methods to be exchanged without changing the rest of the stack.

### `od_stack/sources.py`

Loads observation and reference data.

The current implementation reads the synthetic observation files generated by `obs_generator.py`.

### `od_stack/iod.py`

Contains Initial Orbit Determination methods.

Current methods include:

- `truth_plus_error` — testing stand-in that intentionally offsets the known reference state
- `gooding`
- `gauss`
- `laplace`

The Orekit IOD methods are two-body baselines and currently perform poorly on the cislunar halo-orbit test case.

### `od_stack/estimation.py`

Contains estimation methods used to refine an initial orbit estimate.

The main current estimator is Orekit Batch Least Squares:

```text
orekit_bls
```

### `od_stack/propagators.py`

Contains trajectory propagation methods.

Current options include:

- `orekit_cr3bp` — CR3BP-style propagation implemented through Orekit
- `cr3bp` — independent SciPy CR3BP propagation
- `keplerian` — two-body Earth-only baseline

### `od_stack/frames.py`

Handles conversions between the nondimensional rotating CR3BP frame and the Earth-centered inertial frame used by the orbit-determination stack.

### `od_stack/orekit_models.py`

Defines the Orekit force models and propagator configuration used to reproduce the Earth-Moon CR3BP inside Orekit.

### `od_stack/results.py`

Evaluates the estimated trajectory and generates:

- `summary.json`
- `trajectory_comparison.csv`
- `results.png`

## Supporting Files

### `cr3bp.py`

Contains shared CR3BP equations of motion, the Jacobi constant calculation, and state transition matrix equations.

### `obs_generator.py`

Generates synthetic angles-only spacecraft observations.

It creates:

```text
data/synthetic_obs.csv
data/synthetic_truth.csv
```

`synthetic_obs.csv` is used as the observation input.

`synthetic_truth.csv` contains the reference trajectory used to evaluate simulation performance.

### `artemis2_vs_cr3bp.py`

Compares CR3BP propagation against NASA Artemis II trajectory data to show where the simplified CR3BP model agrees with and diverges from a real trajectory.

### `stm_check.py`

Tests the CR3BP state transition matrix against direct numerical propagation and shows how small initial-state errors grow over time.

### `tests/test_stack.py`

Contains automated tests for frame conversions, CR3BP propagation, Orekit propagation, IOD wiring, Batch Least Squares, and other parts of the stack.

## Requirements

Python dependencies are listed in `requirements.txt`:

```text
numpy
scipy
matplotlib
astropy
pyyaml
orekit-jpype
pytest
```

Orekit also requires Java. Use JDK 11 or newer.

Some Orekit functionality requires an `orekit-data` directory containing physical and time-system data.

Its location can either be set in `config.yaml`:

```yaml
orekit:
  data_path: /path/to/orekit-data
```

or through the `OREKIT_DATA` environment variable.

On macOS/Linux:

```bash
export OREKIT_DATA=/path/to/orekit-data
```

On Windows PowerShell:

```powershell
$env:OREKIT_DATA="C:\path\to\orekit-data"
```

## Installation

Clone the repository and enter the main Python project folder:

```bash
git clone https://github.com/vadhvaryu/afrl_cislunar.git
cd afrl_cislunar/afrl_cislunar
```

Install the Python dependencies:

```bash
pip install -r requirements.txt
```

## Running the Tests

From the folder containing `config.yaml`:

```bash
python -m pytest -q
```

Some Orekit tests require `orekit-data` to be configured.

## Running the Orbit Determination Stack

Run the default configuration:

```bash
python -m od_stack.run
```

The default configuration is defined in `config.yaml`.

Outputs are written to the configured results directory.

Typical outputs include:

```text
results/
├── results.png
├── summary.json
└── trajectory_comparison.csv
```

## Changing Methods

Methods can be selected in `config.yaml` or overridden from the command line.

For example:

```bash
python -m od_stack.run --estimation none
```

This skips Batch Least Squares and propagates the IOD estimate directly.

```bash
python -m od_stack.run --propagator cr3bp
```

This uses the SciPy CR3BP propagator instead of the Orekit propagator.

```bash
python -m od_stack.run --iod gooding
```

This uses Orekit Gooding IOD.

To compare all available IOD methods:

```bash
python -m od_stack.run --compare-iod
```

## Configuration

The main configuration file is `config.yaml`.

It currently includes settings for:

- Earth-Moon system parameters
- Observation and reference-data files
- IOD method and parameters
- Estimation method
- Propagator
- Output directory and sampling
- Orekit data location

This allows simulation stages to be changed without modifying the main pipeline code.

## Docker / Containerization

Containerization is currently in progress.

The `../docker/orekit-cr3bp/` directory contains an initial Docker setup for running Orekit CR3BP tutorials with Java, Orekit dependencies, and `orekit-data` packaged into the environment.

This Docker work is a starting point toward containerizing the complete cislunar orbit-determination stack.

The full `od_stack` pipeline is not yet fully containerized in the current main branch.

## Current Limitations

The current implementation uses several simplifying assumptions:

- Earth-Moon CR3BP dynamics
- Circular lunar motion in the CR3BP model
- Synthetic observations
- Simplified observer geometry
- A custom Earth-Moon inertial frame
- Orekit built-in IOD methods currently use two-body assumptions

These assumptions allow the team to test the orbit-determination pipeline before moving to more realistic cislunar models and data.
